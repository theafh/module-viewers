# Testing

How module-viewers is verified. `task-viewer` is a Rust binary on axum and sqlx. Design is `ARCHITECTURE.md`, behaviour is `FEATURES.md`, and constraints are `SECURITY.md`.

## Test Design Principles

- Test observable behaviour: parsed rows, chart series, HTTP host checks, and database contents. Where the behaviour depends on process-wide state that a parallel-safe test must not change, such as the inherited git environment or the server's working directory, assert how harvest configures its `git` command instead.
- Keep tests deterministic, isolated, offline, and parallel-safe. Every test owns its state through a per-test temp dir named `task-viewer_<name>_<pid>_<nanos>_<n>`, taken from `unique_temp_dir` in an inline test and from the process-level test's own helper, since `src/test_support.rs` opens `#![cfg(test)]` and `task-viewer` declares no lib target. Tests share no paths, no env overrides of the test process, and no execution-order assumptions, and a process-level test sets its child's environment per spawn. `cargo test` runs them in parallel.
- Cover the success path and one failure path for a behaviour that can fail.
- Match a status, a variant, or a field. Avoid asserting a whole error string when a variant is enough, and assert the stored message when that message is the contract.

## Test Organization

- Tests live in `#[cfg(test)]` modules in the source file they exercise, except a process-level test that spawns the built binary, which lives in `task-viewer/tests/` and reaches that binary through `env!("CARGO_BIN_EXE_task-viewer")`.
- Shared helpers live in `#[cfg(test)]` `src/test_support.rs` (`unique_temp_dir`) for the inline suites, while the process-level test carries its own temp-dir helper on the same pattern. The `[dev-dependencies]` block in `task-viewer/Cargo.toml` adds `tower` with its `util` feature for `tower::ServiceExt::oneshot` tests through `router(state)`, and `rquickjs` for tests that execute the shipped JavaScript. A JavaScript fixture shared by those tests sits in `task-viewer/testdata/`, such as `testdata/browser_guards.js` with its stub DOM: it is the JavaScript counterpart of the `src/test_support.rs` helpers, kept outside `src/` so it adds no Rust module. Those tests run the shipped `static/js/theme-boot.js`, `static/js/theme.js`, and `static/js/dashboard.js` against the fixture, and `theme-boot.js` carries its own storage-throwing test beside the theme toggle's.
- Database tests set a thread-local database path under a unique temp dir and use the current-thread runtime so that path stays on the test thread, while a process-level test that spawns the built binary sets `TASK_VIEWER_DB` in its own per-test temp dir for that child process and needs neither.
- Git tests build a unique temporary repository with `user.email` and `user.name` passed on the command, and with author and committer dates in the environment.

## What Must Be Covered

- Date parsing for frontmatter timestamps and commit timestamps, including a frontmatter timestamp that separates its date from its time with a space instead of `T`.
- Harvest: leave day is the first commit that archives the task with `status: finished`, `status: implemented` as the archived spelling a later commit may rename to `finished`, or `status: deferred`. For a finished task that means the earliest commit whose path lies under `archive` and whose content carries either status, including across renames after that commit: a task archived as `implemented` and later rewritten to `finished` dates from the earlier commit, as does a task written `status:finished` without a space, and so does a quoted status or date, wrapped in one matching pair of single or double quotes, while a file opening with a UTF-8 BOM or blank lines before its frontmatter delimiter charts from its frontmatter dates; a task set to `implemented` while live and archived as `finished` dates from the archive commit; a task committed under `tasks/` as `finished` and later moved into `archive/` changing only its path dates from the move, and a later `updated` bump does not become the ship day; a merge commit that archives the task dates from the merge; an archived task deleted and restored, including a deletion on a branch reached through `--all`, keeps the first archived day and returns no `HarvestError`; a nested folder without its own `.git` dates from the enclosing repository's archived commit, and an `archive` directory above that folder does not count as archiving its live tasks; a SHA-256 repository dates its archived tasks the same way. The walk reads raw paths: a task file name holding a non-ASCII character or a double quote dates from its first archived commit, and so does a task in a nested folder whose name holds a non-ASCII character or a double quote, with no `HarvestError`; a walk record whose path holds a newline is skipped, so a task renamed to such a name keeps its first archived day and returns no `HarvestError`; and the walk parser keeps the next record after a path that is not valid UTF-8. Finished ship day equals that leave day; an inherited `GIT_DIR` must not poison the lookup; a date line in the patch context of the status change must not become the ship day; a status carrying a POSIX ERE metacharacter reaches `git log -G` escaped, so `status:[`, `status:deferred[`, and `status:x{1` date from their archive commit and an escaped `x\.y` does not match an unrelated `xy`; `--git-dir` lookups run from the repository folder, whatever the server's working directory; a `.git` that git cannot read fails the scan instead of falling back to `updated`; a folder outside git falls back to `updated`; deferred tasks have no ship day; live tasks stay live; a folder without `tasks/` is rejected; a committed task file whose content is not valid UTF-8 is skipped instead of failing the scan, and its neighbours keep their rows and dates. A prior content hash that matches a file's bytes reuses its stored leave day without a history walk, a changed hash re-walks only that path, and a folder outside git launches no leave walk. A harvest reads each worktree task file once, keeping the walk's content for the chosen file instead of reading it again. A task file whose name holds a literal backslash charts as one row with that backslash in its path and scope, while every other task keeps its path and date. A glob-named live task takes its `created` and `updated` from its frontmatter, a glob-named archived `open` task and a glob-named archived `finished` task each date from their own commits, and an unrelated file that either glob would match keeps its own path and date. An archived `finished` task whose name is not valid UTF-8 charts as one row under its lossy path carrying a `\u{FFFD}` replacement character, keeps the frontmatter `updated` day as its leave day, logs one warning naming that lossy path and that day, and leaves the neighboring task's path and date unchanged. A valid UTF-8 task name that itself holds a `\u{FFFD}` replacement character charts under its real path with the frontmatter `updated` fallback day and logs no warning. A trailing `#` comment on a frontmatter value charts like the bare value, for a status and for a `created` value, and a frontmatter block closes only on a bare `---` line. A `tasks/` directory that cannot be read fails the scan, so the repository keeps its earlier rows and records the error.
- Harvest ref: a task archived on a branch that is not checked out still counts and keeps that commit's ship day; a task archived on one branch while the checked-out branch holds it live counts once, as the checked-out version; a task version that only a merge commit produced, as when two branches edited one file and the merge combined both edits, dates from that merge commit and outranks an older copy on a branch that is not checked out; an uncommitted archive counts and falls back to the frontmatter `updated` day. Refs that share a commit list once, so a local branch, its upstream, and a symbolic remote HEAD cost one `ls-tree` and one copy of each blob id. The ref listing reads raw paths: a branch-only task whose file name holds a non-ASCII character or a double quote is charted with that branch's commit day as its ship day, with no `HarvestError`. A nested folder without its own `.git` charts a task that exists only on another branch with its path relative to the configured folder, and the enclosing repository's own root `tasks/` stays out of that folder's listing.
- Series: same-week create and ship both count, a leave day before `created` returns the live backlog to zero instead of leaving the task inflated, a ship day before the first created day still appears in the cumulative chart and ends at `counts.shipped_events`, a ship week before the first created week still appears in the weekly chart with its shipped sum, a date before 1970-01-01 folds into the first charted day so every series stays bounded, deferred tasks age until leave and never ship, all-projects radars count by repository, and a single project counts by scope.
- Database: versioned migrations upgrade a version-one and a version-two database without losing rows; a schema version that cannot be read fails start-up with that cause and leaves the file untouched, and a database stamped above `SCHEMA_VERSION` is refused with both versions named and keeps its stamp; a configured path creates its parent directory, a parent that is a file is reported, and an empty configured path is rejected; insert, replace rows, keep rows when a scan error is recorded, and delete a repository with its rows.
- Scan: the worker cap parses unset, in-range, zero, non-numeric, and above-maximum values; Update harvests up to the cap at once, stores every repository's rows, and keeps an earlier store with the missing-tasks error when a folder has no `tasks/` directory. The completed-result buffer stays bounded at the cap plus one: a run drains each harvest as it finishes rather than buffering them all, and reads one repository's prior rows in its own stage just before that repository's harvest starts. Dropping the Update request leaves the detached scan holding the lock until its stores finish, so a second Update's harvest and store wait for it, Remove waits for it, and a normal request still returns the same report.
- Host check: loopback names are accepted with or without port 7880; a POST from another origin is rejected with 403 and leaves no side effect, and a POST whose `Origin` is absent or the opaque `null` falls back to `Sec-Fetch-Site`, where only `cross-site` is rejected. A dashboard read that names a `flash` token is accepted only from the dashboard's own page: whatever its method (`GET` or `HEAD`) and however the key is spelled, a `cross-site` or `same-site` read is rejected with 403, while a `same-origin`, `none`, or header-less navigation still renders and consumes the banner.
- Browser guards: the shipped `static/js/theme-boot.js`, loaded from `<head>`, applies a stored theme before the body loads and keeps the default theme when `localStorage` throws, with no uncaught error.
- Security headers: a page, a host-rejected 403, a `/static` file response, and the router's own 404 carry `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, and `Content-Security-Policy: frame-ancestors 'none'`, and the CSP leaves the pages' inline and static scripts running.
- Static asset caching: the dashboard and repositories pages reference the content-derived version the server computed, the version changes when either a root-level or a nested static file changes, page responses carry `Cache-Control: no-store` while `/static` responses carry `Cache-Control: public, max-age=31536000, immutable`, and every `/static/...` URL either page emits carries the version.
- Shutdown: SIGTERM and SIGINT each let an in-flight store finish and the process exit on its own inside the launcher's five-second window.

## Running the Suite

- `make format` runs rustfmt.
- `make lint` runs clippy with warnings denied.
- `make test` runs `cargo test` with warnings denied.
- `make audit` runs `cargo audit` when dependencies change.
