# Testing

How module-viewers is verified. `task-viewer` is a Rust binary on axum and sqlx. Design is `ARCHITECTURE.md`, behaviour is `FEATURES.md`, and constraints are `SECURITY.md`.

## Test Design Principles

- Test observable behaviour: parsed rows, chart series, HTTP host checks, and database contents. Where the behaviour depends on process-wide state that a parallel-safe test must not change, such as the inherited git environment or the server's working directory, assert how harvest configures its `git` command instead.
- Keep tests deterministic, isolated, offline, and parallel-safe. Every test owns its state through a per-test temp dir named `task-viewer_<name>_<pid>_<nanos>_<n>`, taken from `unique_temp_dir` in an inline test and from the process-level test's own helper, since `src/test_support.rs` opens `#![cfg(test)]` and `task-viewer` declares no lib target. Tests share no paths, no env overrides of the test process, and no execution-order assumptions, and a process-level test sets its child's environment per spawn. `cargo test` runs them in parallel.
- Cover the success path and one failure path for a behaviour that can fail.
- A test that passes a wall-clock deadline for process work carries the measured process-start latency that justifies it, and warms the stand-in or retries rather than guessing a constant; the measured worst case and the load it was taken under live beside the deadline.
- Match a status, a variant, or a field. Avoid asserting a whole error string when a variant is enough, and assert the stored message when that message is the contract.

## Test Organization

- Tests live in `#[cfg(test)]` modules in the source file they exercise, except a process-level test that spawns the built binary, which lives in `task-viewer/tests/` and reaches that binary through `env!("CARGO_BIN_EXE_task-viewer")`; the launcher tests, which live in `task-viewer/src/launcher_tests.rs` behind `#![cfg(test)]` and drive `scripts/task-viewer.sh` through a bash subprocess; and a shell suite that drives a shell entry point, which lives in `scripts/tests/*.sh` and builds its own throwaway root and home for each case.
- Shared helpers live in `#[cfg(test)]` `src/test_support.rs` (`unique_temp_dir`) for the inline suites, while the process-level test carries its own temp-dir helper on the same pattern. The `[dev-dependencies]` block in `task-viewer/Cargo.toml` adds `tower` with its `util` feature for `tower::ServiceExt::oneshot` tests through `router(state)`, and `rquickjs` for tests that execute the shipped JavaScript. A JavaScript fixture shared by those tests sits in `task-viewer/testdata/`, such as `testdata/browser_guards.js` with its stub DOM: it is the JavaScript counterpart of the `src/test_support.rs` helpers, kept outside `src/` so it adds no Rust module. Those tests run the shipped `static/js/theme-boot.js`, `static/js/theme.js`, `static/js/dashboard.js`, and `static/js/repositories.js` against the fixture, where `repositories.js` carries the delegated Remove confirmation, and `theme-boot.js` carries its own storage-throwing test beside the theme toggle's.
- Database tests set a thread-local database path under a unique temp dir and use the current-thread runtime so that path stays on the test thread, while a test that spawns work onto other threads uses the multi-thread flavor and still opens its pool on the test thread, since every spawned task takes the pool from `AppState` instead of opening the database itself, and a process-level test that spawns the built binary sets `TASK_VIEWER_DB` in its own per-test temp dir for that child process and needs neither.
- Git tests build a unique temporary repository with `user.email` and `user.name` passed on the command, and with author and committer dates in the environment.

## What Must Be Covered

- Date parsing for frontmatter timestamps and commit timestamps, including a frontmatter timestamp that separates its date from its time with a space or a lowercase `t` instead of `T`, a timestamp with `Z` or a numeric offset, a `±HH:MM`, `±HHMM`, or hour-only `±HH` offset included, charted on its UTC day, a space between the time and its offset, a minute-precision wall time converted across midnight, a timestamp with no zone read as `Europe/Berlin`, and a multi-byte offset tail that keeps the date prefix instead of panicking.
- Harvest: leave day is the first commit that archives the task with `status: finished`, `status: implemented` as the archived spelling a later commit may rename to `finished`, or `status: deferred`. For a finished task that means the earliest commit whose path lies under `archive` and whose content carries either status, including across renames after that commit: a task archived as `implemented` and later rewritten to `finished` dates from the earlier commit, as does a task written `status:finished` without a space, and so does a quoted status or date, wrapped in one matching pair of single or double quotes, and a quoted status padded with spaces inside its quotes, while a file opening with a UTF-8 BOM, with blank lines before its frontmatter delimiter, or with trailing whitespace after the opening `---` still parses its frontmatter, so its `created` and `updated` chart and its archived status still matches the archive walk; a task set to `implemented` while live and archived as `finished` dates from the archive commit; a task committed under `tasks/` as `finished` and later moved into `archive/` changing only its path dates from the move, and a later `updated` bump does not become the ship day; a merge commit that archives the task dates from the merge; an archived task deleted and restored, including a deletion on a branch reached through `--all`, keeps the first archived day and returns no `HarvestError`; a nested folder without its own `.git` dates from the enclosing repository's archived commit, and an `archive` directory above that folder does not count as archiving its live tasks; a SHA-256 repository dates its archived tasks the same way. The walk reads raw paths: a task file name holding a non-ASCII character or a double quote dates from its first archived commit, and so does a task in a nested folder whose name holds a non-ASCII character or a double quote, with no `HarvestError`; a walk record whose path holds a newline is skipped, so a task renamed to such a name keeps its first archived day and returns no `HarvestError`; and the walk parser keeps the next record after a path that is not valid UTF-8. Finished ship day equals that leave day; an inherited `GIT_DIR` must not poison the lookup; a date line in the patch context of the status change must not become the ship day; a status carrying a POSIX ERE metacharacter reaches `git log -G` escaped, so `status:[`, `status:deferred[`, and `status:x{1` date from their archive commit and an escaped `x\.y` does not match an unrelated `xy`, while a status padded with spaces inside its quotes, in either quote style, dates from its archive commit and a quoted `openx` never answers `open`; `--git-dir` lookups run from the repository folder, whatever the server's working directory; a `.git` that git cannot read fails the scan instead of falling back to `updated`; a folder outside git falls back to `updated`; deferred tasks have no ship day; live tasks stay live; a folder without `tasks/` is rejected; a committed task file whose content is not valid UTF-8, or whose content is larger than 4 MiB, is skipped instead of failing the scan, and its neighbours keep their rows and dates. A prior content hash that matches a file's bytes reuses its stored leave day without a history walk, a changed hash re-walks only that path, and a folder outside git launches no leave walk. A harvest keeps the walk's content for the chosen worktree file instead of reading it again, and retains that text only while the running total stays within the 8 MiB cache budget, so a `tasks/` tree larger than the budget re-reads the rows it evicted one file at a time and every task in it still charts. A working-tree task file that cannot be read, is not valid UTF-8, or is larger than 4 MiB warns once with its path, its metadata byte count, and its reason, charts no row, and still claims its task name so an older committed copy never charts under it, while a file without the task-name shape stays at debug level. A committed blob skipped for the same reasons warns with its own reason rather than "no frontmatter", and a vanished object keeps its own missing case. An enclosing-repository probe that does not start, exits nonzero for a reason other than git's not-a-repository answer, or prints fewer than the three lines it was asked for fails the scan with that reason in the logged error, while a folder outside git charts from its files silently; a failed stdout drain fails the command instead of charting a partial listing, and a `cat-file` parse failure reports git's first stderr line. A task file whose name holds a literal backslash charts as one row with that backslash in its path and scope, while every other task keeps its path and date. A glob-named live task takes its `created` and `updated` from its frontmatter, a glob-named archived `open` task and a glob-named archived `finished` task each date from their own commits, and an unrelated file that either glob would match keeps its own path and date. An archived `finished` task whose name is not valid UTF-8 charts as one row under its lossy path carrying a `\u{FFFD}` replacement character, keeps the frontmatter `updated` day as its leave day, logs one warning naming that lossy path and that day, and leaves the neighboring task's path and date unchanged. A valid UTF-8 task name that itself holds a `\u{FFFD}` replacement character charts under its real path with the frontmatter `updated` fallback day and logs no warning. A trailing `#` comment on a frontmatter value charts like the bare value, for a status and for a `created` value, and a frontmatter block closes only on a bare `---` line. An empty `status:` charts no row and logs one warning naming its path, and an `updated` value that does not parse charts the task on its `created` day and logs one warning naming the path and the raw value. A `tasks/` directory that cannot be read fails the scan, so the repository keeps its earlier rows and records the error. The `TASK_VIEWER_GIT_TIMEOUT_SECS` deadline parses unset, in-range, zero, negative, non-numeric, and above-maximum values; both git runners wake on stdout end before polling for the exit, and a child that closes stdout and keeps running still times out.
- Harvest ref: a task archived on a branch that is not checked out still counts and keeps that commit's ship day; a task archived on one branch while the checked-out branch holds it live counts once, as the checked-out version; a task version that only a merge commit produced, as when two branches edited one file and the merge combined both edits, dates from that merge commit and outranks an older copy on a branch that is not checked out; an uncommitted archive counts and falls back to the frontmatter `updated` day. Refs that share a commit list once, so a local branch, its upstream, and a symbolic remote HEAD cost one `ls-tree` and one copy of each blob id. The ref listing reads raw paths: a branch-only task whose file name holds a non-ASCII character or a double quote is charted with that branch's commit day as its ship day, with no `HarvestError`. A nested folder without its own `.git` charts a task that exists only on another branch with its path relative to the configured folder, and the enclosing repository's own root `tasks/` stays out of that folder's listing.
- Series: same-week create and ship both count, a leave day before `created` returns the live backlog to zero instead of leaving the task inflated, a ship day before the first created day still appears in the cumulative chart and ends at `counts.shipped_events`, a ship week before the first created week still appears in the weekly chart with its shipped sum, a date before 2005-04-07, the earliest day git records a commit, folds into the first charted day and logs one warning naming its repository, path, and date so every series stays bounded, deferred tasks age until leave and never ship, all-projects radars count by repository, and a single project counts by scope.
- Database: versioned migrations upgrade a version-one and a version-two database without losing rows; a schema version that cannot be read fails start-up with that cause and leaves the file untouched, and a database stamped above `SCHEMA_VERSION` is refused with both versions named and keeps its stamp; the whole migration of a fresh file runs in one `BEGIN IMMEDIATE` transaction with the schema-version read inside it and one `COMMIT` after the last step, two starts against one fresh file serialize their migration and leave one `content_hash` column with a later start succeeding, a database stamped below version three that already carries `content_hash` upgrades cleanly, and a forced migration failure names its version and path, leaves the prior version, and lets a later start succeed; a stored row that does not parse logs one warning naming its repository, path, and value; a configured path creates its parent directory, a parent that is a file is reported, an empty configured path is rejected, a value padded with spaces opens the unpadded file, and a value that is not valid UTF-8 is refused with `TASK_VIEWER_DB` named; insert, replace rows, keep rows when a scan error is recorded, and delete a repository with its rows.
- Scan: the worker cap parses unset, in-range, zero, non-numeric, and above-maximum values; Update harvests up to the cap at once, stores every repository's rows, and keeps an earlier store with the missing-tasks error when a folder has no `tasks/` directory. The completed-result buffer stays bounded at the cap plus one: a run drains each harvest as it finishes rather than buffering them all, and reads one repository's prior rows in its own stage just before that repository's harvest starts. Dropping the Update request leaves the detached scan holding the lock until its stores finish, so a second Update's harvest and store wait for it, Remove waits for it, and a normal request still returns the same report. Repeated Update clicks that arrive while a scan runs share one follow-up scan, which starts after the running scan finishes and harvests a file written after that run read the folder, so the clicks store twice in total and each reports the follow-up's own banner; a click after the follow-up has taken the scan lock runs a scan of its own, the follow-up still stores when every joined request disconnects, and a follow-up that ends without a result redirects every joined click with the stopped error while the next click scans again. An Update that attempted no repository reports `Nothing to update.` instead of a clean update, and a run that fails some repositories reports the count and each failed repository's reason. `POST /repositories/{id}/scan` harvests only the named repository and answers an unknown id with `repository-not-found` and a folder without `tasks/` with `no-tasks-directory`; `GET /status` reports `scanning`, the worker cap, the configured repository count, the newest parseable scan stamp, and the failed-repository count, and a dashboard loaded while the scan lock is held marks itself busy, names the configured repository count, and polls until `scanning` reads false. The dashboard header names the oldest successful scan stamp in scope and the count of repositories in scope that are stale or failing, where a stamp that does not parse counts its repository as stale, and the Update banner names the number of task files the run skipped when that number is non-zero. A failed git history read stores the fixed sentence followed by that failure's first line, trimmed and cut at 200 characters, so the repository names a cause.
- Repositories: one grouped select reports each repository's total and live row counts, including a zero count for a repository with no stored rows, and the page renders the pair beside the stamps while a never-scanned repository reads `not scanned yet` instead of a pair of zeros. Each name links to `/?project=<id>`. Stored stamps render as human local times against a fixed reference instant and zone, with `N days ago` once the UTC day difference reaches one, and a stamp that does not parse keeps its raw text. Relocate writes the picked canonical path, keeps every stored row, and leaves a fresh scan stamp; a path another repository stores is refused with both repositories unchanged. Add identifies a duplicate clone by its origin URL and a second worktree by its shared git common directory, holds the path without storing it, names the existing repository on the page, and stores it once the confirm token is posted. The stylesheet keeps `min-width: 0` on `.repo-list div` and `overflow-wrap: anywhere` on the path class, with the action forms in one column at the row end.
- Task list: `GET /tasks` renders every stored row for All projects, and each of `project`, `kind`, `scope`, `q`, `date`, `from`, and `to` narrows the list to the rows it names; a weekly bar, a calendar day, and a radar spoke link to the list with the filter that reproduces their count, where the first charted week omits its lower bound and the last omits its upper bound so a folded pre-floor or after-today event still appears; every chart card's Show data table carries one row per payload series row. The task list carries a GET form with a search input bound to `q`, a scope select offering the current project's scopes plus All scopes, a Show button, and hidden `project`, `kind`, `date`, `from`, and `to` fields that round-trip the current filter; an Export CSV link carries those filters, and `GET /tasks.csv` returns the same filtered rows as an attachment with a header row and comma, quote, and line-break quoting.
- Host check: loopback names are accepted with or without port 7880; a POST from another origin is rejected with 403 and leaves no side effect, and a POST whose `Origin` is absent or the opaque `null` falls back to `Sec-Fetch-Site`, where a `cross-site` or `same-site` value is rejected with 403 while `same-origin`, `none`, or an absent header still submits. A dashboard read that names a `flash` token is accepted only from the dashboard's own page: whatever its method (`GET` or `HEAD`) and however the key is spelled, a `cross-site` or `same-site` read is rejected with 403, while a `same-origin`, `none`, or header-less navigation still renders and consumes the banner. The flash store keeps at most `FLASH_CAPACITY` banners and names no slot for a token that is not its canonical decimal spelling: an insert evicts the oldest first, while a restore holds the same bound and never evicts the slot it puts back, dropping the oldest banner other than the one it restored. A page request names a banner only by a code from the closed banner set: every code in the set round-trips through `Banner::from_code` to the banner it names, so a code outside the set, or a notice code in the `error` field, renders no banner and no query text reaches the page.
- Browser guards: the shipped `static/js/theme-boot.js`, loaded from `<head>`, applies a stored choice before the body loads, otherwise the operating system's colour preference, and falls back to the default theme only when neither is available, with no uncaught error.
- Security headers: a page, a host-rejected 403, a `/static` file response, and the router's own 404 carry `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, and `Content-Security-Policy: frame-ancestors 'none'`, and the CSP leaves the pages' inline and static scripts running. The embedded chart payload is the JSON serialized with every `<` written as `\u003c` while the bytes pass, so a repository name holding `</script><b>` closes nothing and the payload holds no raw `<`.
- Static asset caching: the dashboard and repositories pages reference the content-derived version the server computed, the version changes when either a root-level or a nested static file changes, page responses carry `Cache-Control: no-store` while `/static` responses carry `Cache-Control: public, max-age=31536000, immutable`, and every `/static/...` URL either page emits carries the version.
- Shutdown: SIGTERM and SIGINT each let an in-flight store finish and the process exit on its own inside the launcher's five-second window.
- Launcher process safety: two concurrent `start` invocations serialize on one lock, one reports the start and the other an already-running server, and the loser leaves the winner's PID file in place, which a following `stop` removes while leaving no live process; a lock directory whose recorded PID is not alive is reclaimed, and two invocations racing on one stale lock leave exactly one running server; a lock whose recorded PID belongs to a live process whose recorded command line does not name this launcher is reclaimed instead of waited for, so a PID the system reused cannot wedge the launcher, while a live holder whose command line does name it is waited for; a holder whose lock was renamed away before it entered the critical section re-acquires the lock instead of running beside the new holder; a `status` waits for a lock holder before reading the PID file; `is_ours` accepts an absolute binary path, the same path with a trailing argument, a path relative to the checkout, and a bare name on `PATH`, and rejects a path outside the checkout; a stop aimed at an unrelated PID sends it no signal; a stop whose process survives `kill -9` exits non-zero and does not report a stop; a forced start timeout leaves no live server; and an exported `TASK_VIEWER_PORT` does not change the port the launcher's server binds.
- Audit gate: the recorded `vendor/sqlx-sqlite.sha256` lists the tracked files in path order and leaves out an ignored `*.orig`, the verification passes on an unchanged tree, and it fails on a changed byte, an added file, a deleted file, a missing record, and a listing that itself fails, which leaves the record unchanged. The rsa check passes when `cargo tree -i rsa` writes only its `nothing to print.` warning and fails when the reverse listing names `rsa`.

## Running the Suite

- `make format` runs rustfmt.
- `make lint` runs clippy with warnings denied.
- `make test` runs `cargo test` with warnings denied, then `scripts/tests/launcher-build-truth.sh`, which drives copies of the launcher and installer in throwaway roots and homes: the locked build command in the launcher and `make build`, the missing-cargo failure, rustup cargo winning over a Homebrew-first PATH, one build per toggle, the installer's icon-cache and desktop-database checkmarks, the detach branch without python3, and the pinned toolchain. It then runs `scripts/tests/audit-gate.sh`, which drives the vendored-tree digest check and the rsa check against throwaway git roots and a fake `cargo`.
- `make audit` runs `cargo audit`, the `vendor/sqlx-sqlite.sha256` verification, and the `cargo tree -i rsa` reachability check when dependencies change.
