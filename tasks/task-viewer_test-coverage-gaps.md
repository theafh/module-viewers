# Close the promised test coverage gaps

## Goal

`TESTING.md`'s promised scenarios each have a test that would fail if the behavior regressed: a quoted date value, a committed blob over 4 MiB skipped rather than charted, and a signal delivered while a store is in flight, together with a second run that holds a store past the grace and proves the open store rolls back. The graceful-shutdown test no longer races another process for its port, leaves no live server behind after a panic, cleans its scratch directory on every path, asserts against the documented grace window, and its failure messages state what actually happened.

## Context

- Build order: ships after `task-viewer_startup-diagnostics.md`.
- `TESTING.md` lists scenarios with no test or only a partial one.
- `task-viewer/tests/graceful_shutdown.rs` sends its signal before any scan exists, binds port 0 and drops the listener before the child binds, has no `Drop` guard, and measures elapsed time from a start taken before the signal while its wait window starts after it.
- `task-viewer` declares no library target: `task-viewer/Cargo.toml` carries no `[lib]` and `task-viewer/src/main.rs` declares `mod web;`, so the process-level test reaches the binary only through `env!("CARGO_BIN_EXE_task-viewer")` and can neither name `web::SHUTDOWN_GRACE` nor install a `cfg(test)` hook in the child process.
- `task-viewer/src/launcher_tests.rs` uses `std::os::unix::fs::PermissionsExt` but its module declaration is gated only on `test`, so a non-unix `cargo test` fails to compile. Further unix-only test sites share that gap: `task-viewer/src/harvest.rs`'s `#[cfg(test)] mod tests` imports `std::os::unix::ffi::OsStringExt` and `std::os::unix::fs::PermissionsExt` unconditionally, where `OsString::from_vec` sits in the `commit_non_utf8_named_task` helper and `PermissionsExt::set_mode` with `fs::set_permissions` sits in the `fake_git_script` helper beside the one test, `harvest_fails_on_an_unreadable_tasks_subdirectory`, that calls `fs::set_permissions` directly, and two `#[tokio::test]` functions in `task-viewer/src/web.rs` set file modes through `PermissionsExt`.
- This task ships after [task-viewer_startup-diagnostics.md](archive/task-viewer_startup-diagnostics.md), which logs `listener.local_addr()` only after a successful bind and rejects a zero port, so the shutdown test reads the bound port from that post-bind line.
- Prior art: [task-viewer_graceful-shutdown.md](archive/task-viewer_graceful-shutdown.md) delivered the shutdown behavior; these are the test gaps that let it regress.

## Approach

- Add the promised tests where each can observe its behavior, since the target functions are private and the crate exposes no library target: in `task-viewer/src/harvest.rs`'s `#[cfg(test)] mod tests`, a frontmatter `created` wrapped in one matching pair of single quotes and again in double quotes charts on the day it names, like its bare spelling, and a task file committed over `MAX_TASK_FILE_BYTES` contributes no row while a sibling task in the same commit still charts, the skip `ARCHITECTURE.md` states as "A task file larger than 4 MiB contributes no row"; in `task-viewer/tests/graceful_shutdown.rs`, a signal sent while a store is in flight, driven by two process-level runs over one shared scratch database — one whose store pause sits inside the grace, whose stored rows the test reads back from the child's database file with `sqlx` after the child exits, and one whose store pause runs past the grace, so its transaction rolls back. The test seeds the `repositories` table with `sqlx` once the child has created the schema, triggers Update with a `POST /scan` carrying the origin and host headers the request guard requires, waits for the marker file the store hook writes, and only then sends the signal, so the in-flight run's committed rows become the past-grace run's pre-run state and the rollback assertion compares against a real row set rather than an empty table.
- Give the shutdown test a deterministic store pause without `cfg(test)` code in the spawned binary: read a test-only `TASK_VIEWER_TEST_STORE_PAUSE_MS` override in `web::AppState::new` in `task-viewer/src/web.rs`, beside the existing `TASK_VIEWER_SCAN_WORKERS` read, where a whole number of milliseconds replaces the default `store_hook` with one that sleeps that long inside `db::replace_tasks`, so the test holds a store open across the signal. That hook also writes a marker file once the sleep has begun, and the test waits for that marker before it sends the signal, so "in flight" is an observed fact rather than a timing bet. `AppState::store_hook` is private to the `web` module, so the override is read where that field is built rather than in `task-viewer/src/main.rs`, whose `RUST_LOG` and `TASK_VIEWER_PORT` reads stay the only environment reads there. Name the override in the environment paragraph of `ARCHITECTURE.md` and leave it unset everywhere else.
- Start the child on a candidate `TASK_VIEWER_PORT` and, when it exits before serving with a bind error, retry the next candidate port, taking the port it actually bound from the post-bind `task-viewer listening on http://{addr}` line that task-viewer_startup-diagnostics.md delivers; the test binds no listener itself, so two runs started together cannot take each other's port.
- Add a `Drop` guard that kills and waits for the child and removes the scratch directory.
- Assert the drain against the documented four-second grace, declared as a local `GRACE: Duration = Duration::from_secs(4)` in the test whose doc comment names `web::SHUTDOWN_GRACE` in `task-viewer/src/web.rs` as the single source it mirrors, since the binary exposes no library target to import it from.
- Correct the two failure messages that state the opposite of what happened, and the doc comment that claims "drains" with no assertion.
- Gate every unix-only test site on `unix`: `#[cfg(all(test, unix))]` on `task-viewer/src/main.rs`'s `mod launcher_tests;`; in `task-viewer/src/harvest.rs`'s test module, `#[cfg(unix)]` on the two `use std::os::unix::…` lines, on the `fake_git_script` and `commit_non_utf8_named_task` helpers, and on every test that calls either helper or calls `fs::set_permissions` directly, since gating the imports alone takes `PermissionsExt` and `OsStringExt` out of scope for the helpers and gating the helpers alone leaves their callers naming an absent function; and `#[cfg(unix)]` on the two `task-viewer/src/web.rs` tests that set file modes. In `task-viewer/src/harvest.rs`'s test module, gate `register_test_git`, `clear_test_git`, and the `git_override` import, which lose their only non-unix callers once the `web.rs` ref-union test is gated, and gate `dispatch_script`, `register_fake_git`, `register_fake_git_with_deadline`, and `clear_fake_git`, which lose theirs once the harvest tests calling `fake_git_script` are gated, so a non-unix build does not fail on `dead_code` or `unused_imports`. Add a source-shape test beside them that reads `main.rs`, `harvest.rs`, `web.rs`, and `launcher_tests.rs`, asserts each unix-only site carries its gate, includes the `mod launcher_tests;` declaration, the `PermissionsExt` import in `launcher_tests.rs`, and those six helpers plus the `git_override` import among the sites it checks, and skips only its own body and the scan's own helper functions, while `fake_git_script` and `commit_non_utf8_named_task` stay in the scanned site set.

## Acceptance

- Each of the three promised scenarios has a test that fails when its behavior is reverted, checked by temporarily reverting each scenario's behavior in turn.
- The in-flight run, with the store pause inside the grace, passes ten consecutive runs with no timing-based flake.
- The in-flight run waits for the store hook's marker file before it sends the signal, so the signal provably arrives while a store is open.
- A panic in the shutdown test leaves no `task-viewer` process running and no scratch directory behind.
- The elapsed assertion fails when the test's `GRACE` mirror and `web::SHUTDOWN_GRACE` disagree: in the past-grace run, with a store held in flight longer than the grace, the server exits no earlier than the mirrored grace and still inside the launcher's window, so lowering `web::SHUTDOWN_GRACE` alone fails the run.
- The in-flight run's stored rows are in the child's database after it exits, while the past-grace run leaves the repository's rows exactly as they stood before the run, so the two runs distinguish a finished store from a rolled-back one.
- The test binds no listener of its own: it starts the child on a candidate port, retries the next candidate when the child reports the address in use, and takes the bound port from the child's post-bind listening line, so two runs started together cannot take each other's port.
- The corrected failure messages name the actual condition.
- A source-shape test in `harvest.rs`'s test module finds, across `main.rs`, `harvest.rs`, `web.rs`, and `launcher_tests.rs`, every `use std::os::unix::…` line, every function whose body calls `fs::set_permissions`, `PermissionsExt::set_mode`, or `OsString::from_vec`, every test that calls `fake_git_script` or `commit_non_utf8_named_task`, and the `mod launcher_tests;` declaration, the `PermissionsExt` import in `launcher_tests.rs`, and the six helpers `register_test_git`, `clear_test_git`, `dispatch_script`, `register_fake_git`, `register_fake_git_with_deadline`, and `clear_fake_git`, plus the `git_override` import, and asserts each sits under a `unix` cfg gate, so the unix-only test code is excluded from a non-unix `cargo test` build. The test's own body and the scan's own helper functions are excluded from its scan, while `fake_git_script` and `commit_non_utf8_named_task` stay in the scanned set.
- `ARCHITECTURE.md` names the test-only store-pause override with its default of unset, beside `TASK_VIEWER_PORT`.
