# Treat an archived implemented-to-finished change as a status rename

## Goal

Harvest treats `status: implemented` on an archived task file as an earlier spelling of `status: finished`. A finished task's leave day, and with it its ship day, becomes the committer day of the earliest commit in which the file sits under an `archive` directory with either status. When a repository moved its archived tasks from `implemented` to `finished` in one commit, each task now ships on the day it was first archived as implemented, and the rename commit no longer stacks all of them onto one day. A task that was `implemented` while still live in `tasks/` and archived as `finished` later keeps its current dates, because only the archived spelling counts as the rename. That keeps the ship day equal to the leave day, as `ARCHITECTURE.md` states.

## Context

- `fn first_status_commit_date` in `task-viewer/src/harvest.rs` builds the pickaxe from the task's current status alone (`status: {status}` via `-S`, then `^status:[[:space:]]*{status}` via `-G`). `fn run_git_log` runs `git log --follow --diff-merges=first-parent --no-patch --format=%cI` and keeps the earliest date it parses, and `fn git_pickaxe` chooses between the `--git-dir` route and the `-C` route and turns a git failure into `HarvestError::Git`.
- `fn classify` in `harvest.rs` makes an archived file `Finished` only when its status is `finished`, so the rename question arises only for files whose current status is `finished`.
- In one configured repository, a single commit rewrote archived tasks from `status: implemented` to `status: finished`. Because `-S "status: finished"` finds that commit first, every task it touched charts its ship day on that day. Those tasks' histories carry `status: implemented` from the commit that archived them, often weeks earlier.
- `--follow` walks a task file back across its move from `tasks/` to `tasks/archive/`. So an `implemented` hit from the live phase, under the current lifecycle of `implemented`, then `audited`, then `finished`, also shows up in that walk. The file's path in each commit is what tells the two phases apart.
- `CHARTER.md` under `## Key Invariants` defines the ship day in the bullet that begins "A shipped task is an archived task whose status is `finished`." `ARCHITECTURE.md` defines the leave day and ship day in the bullet that begins "The leave day of a finished or deferred task". This task rewrites both, at the user's request.

## Approach

1. In `harvest.rs`, date a finished task from the earliest commit in which its path lies under a directory named `archive` and its content at that commit carries `status: finished` or `status: implemented`, so the commit that first moves the file into `archive/` qualifies even when it edits no status literal. Replace the pickaxe in `fn first_status_commit_date` for finished tasks with one `git log --follow --diff-merges=first-parent --name-only --format='%cI %H' --all -- <rel>` walk: drop `--no-patch`, because it suppresses the path output beside `--name-only`, and read each record as one line carrying the committer date, then the commit id, followed by the path block that belongs to it. `parse_iso_date` in `dates.rs` accepts only a `%Y-%m-%d` prefix, so a path line never becomes a date. For each commit whose path lies under `archive`, read the file's content at that commit through the same routing `fn git_pickaxe` uses: express each read as the `<commit>:<path>` expression taken from that record and feed the whole set to `read_blobs(repo, dir, blobs)` in one batch per task, resolving `git_dir(repo)` once and using the `--git-dir`/`--work-tree` route when it is `Some`, while when it is `None` run the same single batch through `git -C repo` so a folder without its own `.git` still dates from the enclosing repository. A record whose `<commit>:<path>` expression names an object missing at that commit, as a deletion commit in the followed history or a branch deletion reached through `--all` produces, counts as no qualifying commit and is skipped before the batch is fed; keep the earliest date whose blob's `frontmatter()` map holds a `status` field equal to `finished` or `implemented`; that parse splits each frontmatter line at `:` and trims both sides, so `status:finished` and `status:  finished` match the same as `status: finished`, and a blob with no frontmatter block yields no map and no match. Deferred and live tasks keep their current lookup.
2. Keep the failure handling as it is, with the no-`.git` outcome stated rather than folded into `HarvestError::Git`. A lookup that `git` cannot run in a folder whose `git_dir(repo)` is `Some` still ends in `HarvestError::Git`. A folder with no `.git` of its own but inside an enclosing repository takes the `-C` route step 1 names, so its lookup runs against the enclosing repository and dates the task from that repository's earliest qualifying archived commit, exactly as step 1 states. Only a folder outside any git repository, where `git_dir(repo)` is `None` and the `-C` call also fails to run, returns `Ok(None)` and falls back to the frontmatter `updated` day. A lookup that runs and finds no qualifying commit also falls back to the frontmatter `updated` day.
3. Rewrite the `CHARTER.md` shipped-task invariant in place: the ship day is the commit that first archived the task as `finished`, or as `implemented` when `implemented` was the archived spelling that a later commit renamed. Rewrite the `ARCHITECTURE.md` leave-day bullet in place to state the same rule and how the archived path is read per commit, and replace the bullet's mechanism sentences that describe the finished-task lookup: the `-S` then `-G` clause becomes the `--name-only` archived-path walk with its per-commit content read, the `--no-patch` clause states that the walk takes names and content instead of patch lines, and the newest-first-without-`--reverse` sentence states that the walk reads every commit whose path lies under `archive` and keeps the earliest date. State in the same bullet that the `-S`/`-G` pickaxe remains the lookup for deferred tasks, and keep its merge sentence true for the finished-task walk: merge commits are diffed against their first parent (`--diff-merges=first-parent`), so a task archived while resolving a merge still matches.
4. Rewrite the harvest bullet of `TESTING.md` `## What Must Be Covered` in place: replace its archived-status clause, "leave day is the first commit that introduces the archived status (`finished` or `deferred`)", with wording that names the archived `implemented` spelling as a source of the leave day, and carry the cases that Acceptance proves in that same bullet. One leave-day clause then states the rule those cases prove.

**Out of scope:**

- Counting a file that is still archived with `status: implemented` as finished. `fn classify` and the `CHARTER.md` definition of a shipped task (an archived task whose status is `finished`) stay as they are.
- Any other status alias, such as `done` or `shipped`, because no configured repository's history carries one.

## Acceptance

- [ ] A harvest test builds a repository where a task is committed under `tasks/archive/` with `status: implemented` on one day and rewritten to `status: finished` on a later day. The test asserts that `ship_date` and `leave_date` both equal the earlier day.
- [ ] A harvest test builds a repository where a task is committed under `tasks/archive/` with `status:finished` (no space after the colon) on one day and rewritten to `status: finished` on a later day. The test asserts that `ship_date` and `leave_date` both equal the earlier day.
- [ ] A harvest test builds a repository where a task is set to `status: implemented` while it is still in `tasks/`, then moved to `tasks/archive/` with `status: finished` on a later day. The test asserts that `ship_date` equals the later day.
- [ ] A harvest test builds a repository where a task is committed under `tasks/` with `status: finished` on one day and a later commit moves it to `tasks/archive/` changing only its path, with the frontmatter `updated` bumped on a still later day. The test asserts that `ship_date` and `leave_date` both equal the move day.
- [ ] A harvest test builds a repository where a merge commit is the commit that archives the task with `status: finished` and neither parent does. The test asserts that `ship_date` and `leave_date` both equal the merge commit's day.
- [ ] A harvest test builds a repository where a task is committed under `tasks/archive/` with `status: implemented` on one day, deleted in a later commit, and restored with `status: finished` on a still later day. The test asserts that `ship_date` and `leave_date` both equal the first day and that no `HarvestError` is returned. A second case in the same test deletes the archived file on a branch commit reached through `--all` and asserts the same dates and the same absence of `HarvestError`.
- [ ] `rg 'Its ship day is the commit that first introduced that status' CHARTER.md` finds nothing, and the rewritten shipped-task bullet names the archived `implemented` rename.
- [ ] The `ARCHITECTURE.md` leave-day bullet states the archived `implemented` rule once, no other `ARCHITECTURE.md` passage still dates a finished task by `status: finished` alone, and the bullet attributes `-S`, `-G`, and `--no-patch` only to the deferred lookup, never to the finished-task lookup.
- [ ] `rg 'introduces the archived status' TESTING.md` finds nothing, the harvest bullet's leave-day clause names the archived `implemented` spelling alongside `finished` and `deferred`, and that same bullet names the cases that Acceptance proves.
- [ ] A harvest test builds a parent repository whose nested folder holds `tasks/` and carries no `.git` of its own, configures that nested folder as a repository, and asserts the task charts the leave day of the parent repository's archived commit without a `HarvestError`.
