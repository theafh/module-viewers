# Bound every git subprocess with a timeout

## Goal

A hung git command cannot hold the scan mutex or a blocking thread forever. The affected repository records a scan error and the rest of Update proceeds.

## Context

`task-viewer/src/harvest.rs` starts every git child with `std::process::Command` and waits on it with no deadline: the single-shot readers call `Command::output()`, and the batch readers spawn a child and call `wait_with_output()`. `## Approach` lists each site. A repository on a stalled network mount, or a git process that blocks on a lock or an external helper, keeps a `spawn_blocking` thread and the scan lock until the process ends.

## Approach

Run each read-only git command through one synchronous helper in `task-viewer/src/harvest.rs` built on `std::process::Command`: it spawns the child, drains stdout and stderr on their own threads while the child runs, accepts an optional stdin payload that it writes from its own thread exactly as the batch readers do today, checks the child against the deadline, and kills the child once the deadline passes. The module, its callers, and `HarvestFn` in `task-viewer/src/web.rs` stay synchronous. The production deadline is a `Duration` constant `GIT_COMMAND_TIMEOUT`, set to 30 seconds and declared beside `GIT_SEARCH_DIRS`; the helper receives its deadline as a `Duration` argument, so its unit test passes a short value such as 100 ms directly and needs no environment override. The same test-only registry entry carries an optional per-repository deadline, and each site asks one deadline accessor for the repository it is working in: under `cfg(test)` the accessor reads that entry and falls back to `GIT_COMMAND_TIMEOUT` when none is registered, and in production it returns `GIT_COMMAND_TIMEOUT`, so a harvest-level hang test registers 100 ms for its fixture repository and drives `git_read`, `blob_days`, `read_blobs`, `existing_object_indices`, `run_git_log`, `archived_leave_lookup`, and `enclosing_prefix` at that deadline with no production signature change (`run_git_log`'s already-present `repo` parameter supplies its lookup). The sites are the single-shot readers `git_read`, `blob_days`, `run_git_log`, `archived_leave_lookup`, and `enclosing_prefix`, plus the batch readers `read_blobs` and `existing_object_indices`; `enclosing_prefix` runs first inside `GitContext::resolve`, and `archived_leave_lookup` runs once per archived task through `leave_dates` → `first_archived_commit_date`. On timeout, return a `HarvestError::Git` with a clear message so `store_outcome` records the existing git error. `read_blobs` and `existing_object_indices` return `Result<_, GitFailure>` as well, and `archived_leave_lookup` propagates their error unchanged with `?` instead of converting it with `to_string()`, so a nested batch-read timeout reaches `first_archived_commit_date` as `GitFailure::Timeout`; each caller that must hand back a `HarvestError` maps `GitFailure` to `HarvestError::Git` at its call site. The helper returns one error enum declared beside it, `enum GitFailure { Timeout(String), Other(String) }`, whose `Display` prints the message `HarvestError::Git` already carries; `LogLookup::Failed` holds a `GitFailure`, and `archived_leave_lookup`, `first_archived_commit_date`, and `enclosing_prefix` return it in their error position, so every arm and fallback matches `GitFailure::Timeout` instead of reading message text: a timeout is final and propagates as the scan error at each of the three points, while `GitFailure::Other` keeps today's fallback and `Ok(None)` handling, `HarvestError` keeps its `Git(String)` variant built from that `Display`, and `git_read` keeps its `Result<String, String>` because no caller of it falls back. A timeout reaches `store_outcome` as a scan error at every existing swallow point rather than being flattened into `None`: `git_pickaxe`'s `LogLookup::Failed(_) => Ok(None)` arm, `first_archived_commit_date`'s `Err(_) => Ok(None)` arm, and `enclosing_prefix`'s `.output().ok()?`, whose `Option<String>` return becomes a `Result<Option<String>, GitFailure>` so `GitContext::resolve` returns `Result<GitContext, GitFailure>` and `harvest_repository` propagates the timeout as `HarvestError::Git`. Each arm keeps its current handling for an ordinary failure, and the no-commit `LogLookup::Miss` / `Ok(None)` path is unchanged, so a folder inside an enclosing repository with no own `.git` (`git.dir` `None`, `inside_repository` `true`) records a scan error instead of being charted from disk with `updated` fallback dates. A timeout is final for that lookup: the `--git-dir` to `-C` fallback in `git_pickaxe` and the `dir=Some` to `dir=None` fallback in `first_archived_commit_date` keep handling a non-timeout failure only, so a timed-out command is never attempted a second time. The harvest-level test reaches its fake git through a test-only override: a `#[cfg(test)]` registry keyed by canonical repository path, in the shape of the existing `walk_count` module, that the git command builders consult in place of `git_bin()`. A test registers an absolute script path for its own fixture repository, so production keeps the `git_bin()` default and no environment variable is set. Keep the current output parsing unchanged.

**Out of scope:** Retrying a timed-out command; the repository is reported and the next Update tries again.

## Acceptance

- Every hang item below registers a 100 ms deadline for its fixture repository through the test-only deadline override, so each item proves its production site returns at that deadline instead of waiting out `GIT_COMMAND_TIMEOUT`.
- A unit test calls the deadline accessor for a repository path with no registered override and asserts it returns `GIT_COMMAND_TIMEOUT`.
- A test runs a stand-in command that sleeps past a short timeout and asserts the helper returns a timeout error and the child is gone.
- A harvest test registers a hanging fake git for its fixture repository through the test-only repository-keyed override and asserts harvest returns `HarvestError::Git` instead of blocking.
- A normal harvest test still returns the expected rows and dates.
- A helper test runs a stand-in command that writes more than one pipe buffer (for example 256 KiB) to both stdout and stderr before exiting, and asserts the helper returns that output instead of a timeout.
- A harvest test whose git hangs for a folder inside an enclosing repository with no own `.git`, holding both a live and an archived task, asserts harvest returns `HarvestError::Git` and charts no row from `updated` fallback dates, so the `git_pickaxe` and `first_archived_commit_date` arms each time out rather than miss.
- A harvest test on that same enclosing-repository fixture, whose fake git answers the earlier `git log` calls and hangs only on `cat-file --batch-check`, asserts harvest returns `HarvestError::Git` and charts no row from the `updated` fallback, proving a nested batch-read timeout reaches `store_outcome` as the scan error.
- A harvest test whose `rev-parse --show-prefix` call hangs asserts harvest returns `HarvestError::Git` instead of treating the folder as outside git.
- A harvest test whose fake git records each invocation asserts that a hanging lookup in a folder with its own `.git` returns `HarvestError::Git` after exactly one invocation, proving the fallback does not retry a timed-out command.
- A harvest test whose fake git wrapper answers every call before the batch read and hangs only on `cat-file --batch` asserts `harvest_repository` returns `HarvestError::Git` for that repository instead of blocking on `read_blobs` or `existing_object_indices`.
- A routing test makes the fake git wrapper hang on the command form each site issues and asserts every production git subprocess site returns at the deadline instead of blocking: `git_read`, `blob_days`, `read_blobs`, `existing_object_indices`, `run_git_log`, `archived_leave_lookup`, and `enclosing_prefix`.
- A harvest test whose fake git exits non-zero on the `--git-dir` lookup and answers the `-C` lookup asserts harvest still returns the expected rows and dates, proving an ordinary failure keeps the fallback while a timeout does not.
