# Make every harvest skip visible with its real cause

## Goal

A working-tree task that cannot be opened, is not UTF-8, or exceeds the size cap leaves one log line naming the path and the reason. A committed blob skipped for the same reasons reports that reason instead of "has no frontmatter". A failing `cat-file` reports git's own stderr instead of a generic parse message. An enclosing-repository probe that exits nonzero for any reason other than the "not a git repository" answer a folder outside git gets fails the scan with git's first stderr line in the error log, a probe that does not start fails the scan with its start error in the same log, and the not-a-repository answer stays silent. A git listing that cannot be read whole fails the scan rather than passing as complete. The cached worktree text stays within a declared budget of 8 MiB instead of holding every task file at once.

## Context

- Build order: first in the harvest cluster. Blocks `task-viewer_harvest-git-failure-cases.md`, which reshapes the same `fn files_on_disk` and `fn union_files` surface, and blocks `task-viewer_guardrail-doc-sync.md`, which documents the failed-enclosing-probe rule this task establishes.
- `task-viewer/src/harvest.rs` owns these paths: `fn files_on_disk` skips on `File::open` failure, read failure, and the size cap with a bare `continue`; the committed-blob path calls `String::from_utf8(body).unwrap_or_default()` and hands an empty string to the frontmatter parser; the `cat-file` reader reports "truncated object header" without git's stderr; `fn enclosing_prefix` collapses every non-timeout `rev-parse` failure to `Ok(None)`, both the spawn-failure arm and the nonzero-exit arm, so a probe that broke charts its folder as outside git; and one git read does `let _ = pipe.read_to_end(&mut buffer);`.
- The finished task [task-viewer_harvest-silent-drops.md](archive/task-viewer_harvest-silent-drops.md) promised "a log line naming it and the reason". These are the paths that promise does not yet cover.
- `task-viewer/src/harvest.rs` also documents a worktree content map whose "never all resident" claim is false for worktree files: `fn worktree_content` already removes each row's text after use, but `fn files_on_disk` first materialises every file's text in one `Vec`, so peak residency is the whole `tasks/` tree. A budget that evicts leaves the evicted path out of `WorktreeFiles`, so `fn worktree_content` takes its fresh read. The read-count assertion in `harvest_reads_each_worktree_task_file_once` needs no change: its fixture is four task files of roughly 100 bytes each, far under any 8 MiB budget, so no row evicts and `take_worktree_read_count(&repo) == 4` still holds.

## Approach

- Warn once per skipped working-tree file with the path, the byte count, and the reason, using the same `has_task_name_shape` gate the warning stream already applies so a stray `README.md` under `tasks/` stays quiet. Take the byte count from the file's metadata length, so a file that cannot be opened or is not UTF-8 still reports its real size rather than a false zero.
- Return a reason enum from the committed-blob reader and log the real cause instead of synthesizing an empty string, so an oversized body and a body that is not UTF-8 each carry their own reason to the warning that names the path, and a vanished object keeps its own distinct missing case rather than folding into a skip reason. Emit that warning from `fn harvest_chosen`, where the `read_blobs` callback holds the reason, and gate it with the same `has_task_name_shape` check the worktree warning uses. `read_blobs` has a second caller, `fn archived_leave_lookup`, which must adopt the enum too and keep treating a non-text answer as no qualifying commit. Update `parse_batch_drains_a_blob_over_the_cap_and_keeps_the_next_one`, which asserts the old `Some(String::new())` shape, and move every other `parse_batch` caller's callback to the reason type.
- Prefer the first line of git's stderr when a `cat-file` or `rev-parse` result cannot be parsed, reading it at `fn run_git_streaming`, the only site that still holds git's stderr when `cat-file` output fails to parse. Keep the outside-git answer silent: a nonzero `rev-parse` whose stderr is git's "not a git repository" message still returns `Ok(None)`. Run the probe with `LC_ALL=C` and match that answer case-insensitively, so a translated git and the older capitalised "Not a git repository" wording both stay silent. Any other nonzero exit returns `GitFailure::Other` carrying git's first stderr line, falling back to a fixed message when stderr is empty; a probe that does not start returns `GitFailure::Other` carrying its start error. A probe that exits zero while printing fewer than three lines also fails the scan with a fixed message, rather than returning `Ok(None)` and charting the folder as outside git. Both reach the scan as `HarvestError::Git`, so the repository keeps its previous rows; `store_outcome` in `web.rs` logs that reason, which is where git's stderr line appears, and stores the fixed `GIT_ERROR` message that the Repositories tab and the run report show.
- Surface a failed stdout drain as a git failure instead of charting a truncated listing: `fn run_git_command`'s stdout thread returns its `read_to_end` error and the command returns `GitFailure::Other` naming that error, so the `for-each-ref`, `ls-tree`, and `rev-parse` readers fail the scan instead of parsing a partial buffer. Extract the drain into a named helper that takes a `Read`, and cover it with an inline test that feeds a short buffer and then an I/O error.
- Bound the cached worktree text with a new `MAX_WORKTREE_CACHE_BYTES` constant of 8 MiB: `fn files_on_disk` records every `.md` file under `tasks/`, including the ones it skips, with its path and lossy flag, so a stray `tasks/README.md` that carries the fields a row needs still charts and the working-tree set stays the same as the committed-blob set, which filters on `.md` alone. The `has_task_name_shape` gate applies to the warning site only. It reads and classifies every file so each skip keeps its warning, and retains its text only while the running retained total stays within the budget, so the budget bounds the retained cache that the peak-residency counter measures and each walk read in flight stays bounded by `MAX_TASK_FILE_BYTES`. An evicted row's fresh read is bounded too: `fn worktree_content` and the outside-git `fn harvest_files` re-read apply the same `.take(MAX_TASK_FILE_BYTES + 1)` cap as the walk.
- Represent each row with three states rather than a bare `Option<String>`, because two states cannot separate an evicted row from a skipped one: `struct WorktreeRow { path: String, lossy: bool, text: Option<String>, skip: Option<SkipReason> }`. The three states behave differently, and the rest of the change follows from them:
  - **Charted**: `text` is `Some`. `union_files` inserts it into `WorktreeFiles`; `fn worktree_content` charts it and frees it after use.
  - **Evicted**: `text` is `None`, `skip` is `None`. The row is over budget, so `union_files` keeps its path in the candidate ranking but inserts nothing into `WorktreeFiles`; `fn worktree_content`'s `remove` misses it and takes the fresh-read fallback; `fn harvest_files`, the outside-git caller, re-reads it one file at a time, so a folder outside git charts every task it holds. A tree larger than the budget therefore reads some files twice, so add a test that charts a tree over it.
  - **Skipped**: `skip` is `Some(reason)`. The row warned once and charts no row. `union_files` claims its name in the `seen` set and pushes no chosen row, so the path still blocks an older committed copy from claiming the name while `fn harvest_chosen` never calls `fn worktree_content` for it and never re-reads it. That is what keeps an oversized file from being read whole and stops a second "has no frontmatter" warning with the wrong reason. This task owns that placeholder; `task-viewer_harvest-git-failure-cases.md` owns only the proof that the ref-union path preserves it.
- Correct every comment the change falsifies, including the "never all resident" one: `harvest_chosen`'s "The chosen set's contents are therefore never all resident.", `harvest_repository_with_prior`'s enclosing-probe comment, `union_files`'s reuse claim and its "the working-tree contents come from the walk that already read them" line, `WorktreeFiles`'s alias doc, `worktree_content`'s empty-content fallback claim, `files_on_disk`'s skip comment, and `parse_batch`'s `Some(String::new())` claim.

**Out of scope:** The `ARCHITECTURE.md` git-fallback sentence that says "a command that exits with an ordinary error keeps the existing fallbacks" is rewritten to state this task's fail-on-other-error rule by [task-viewer_guardrail-doc-sync.md](task-viewer_guardrail-doc-sync.md), which owns the guardrail-doc amendments for the harvest cluster. That same doc task also owns the `TESTING.md` "What Must Be Covered" sentence that says a harvest reads each worktree task file once, which this task's 8 MiB budget makes false for a tree over the budget.

## Acceptance

- A fixture with an oversized, a non-UTF-8, and an unreadable working-tree task produces three warnings, each naming its path, its byte count, and its reason, and none of the three contributes a row.
- A committed non-UTF-8 blob produces a warning that names the encoding or byte reason, not "no frontmatter".
- A committed blob larger than 4 MiB produces a warning that names its path and the size reason, not "no frontmatter".
- A fixture that forces a `cat-file` failure logs git's stderr text.
- A fixture whose enclosing-repository probe exits nonzero with stderr other than git's not-a-repository answer fails the scan with that stderr in the logged error, stores the fixed `GIT_ERROR` message the run report shows, and keeps the repository's previous rows, while a folder outside git charts from its files with no warning.
- A fixture whose enclosing-repository probe fails to start fails the scan with its start error in the logged error, while a folder outside git stays silent.
- A fixture whose enclosing-repository probe exits zero while printing fewer than three lines fails the scan with the fixed message instead of charting the folder as outside git.
- A reader that yields a short buffer and then an I/O error makes the extracted drain helper return git's error, and a `run_git_command` error reaches the scan as `HarvestError::Git` instead of charting a partial listing, proved by the propagation `harvest_every_git_site_returns_at_the_deadline` already exercises.
- A skipped path still wins the candidate ranking while contributing no charted row and emitting no second warning: an oversized, a non-UTF-8, and an unreadable working-tree task each produce exactly one warning, chart no row, and block an older committed copy of the same path from charting.
- Every `harvest.rs` comment the Approach names no longer carries its superseded claim, checked by grepping each for the sentence it replaces.
- The worktree cache holds no more than the declared 8 MiB budget on a fixture larger than it: a peak-residency counter beside `worktree_read_count` never exceeds `MAX_WORKTREE_CACHE_BYTES`, and every task in that fixture still charts, including in a folder outside git.
